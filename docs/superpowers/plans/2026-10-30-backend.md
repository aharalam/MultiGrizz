# MultiGrizz Backend Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for integration; independent runtime/schema subtasks may run in parallel under the project contract.

**Goal:** Deliver a standalone, team-isolated local-Gemma backend and frontend API contract.

**Architecture:** Fastify API verifies Supabase bearer tokens and uses caller-scoped Data API clients. Postgres RLS and same-team foreign keys enforce tenancy. One in-process queue runs bounded Gemma tool loops against local Ollama.

**Tech Stack:** Node 22, TypeScript, Fastify, Zod, Supabase JS, Node test runner/tsx.

**Spec:** `docs/superpowers/specs/2026-10-30-backend-design.md`

## Global constraints

- Team is synonymous with party; no separate parties table.
- No cloud inference or secret credentials in source, tests, logs, or frontend.
- Frontend/backend dependencies and entry points stay independent.
- Deployment/schema status must be accurately reported.

## Review focus

- Untrusted team/squad/agent identifiers and composite references must never cross tenant boundaries.
- Concurrent or repeated run submissions cannot trigger duplicate active squad jobs.
- Model/tool failures, malformed output, and exhausted capacity leave honest visible run states.
- Long context and tool output stay bounded without treating reference content as instructions.
- Origin validation and error handling must not expose credentials or database internals.
